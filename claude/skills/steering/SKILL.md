# ステアリングドキュメント管理スキル

## トリガー

`Skill(steering)` または `/steering` で呼び出す。引数でモードを指定する。

## モード 1: 作成（create）

新機能・大きな変更の開始時にステアリングドキュメントを作成する。

### 手順

1. 現在日付を `YYYYMMDD` 形式で取得する
2. 機能名をケバブケースに変換する（例: "ユーザー認証" → `user-auth`）
3. `.steering/[YYYYMMDD]-[name]/` ディレクトリを作成する
4. 以下の3ファイルをテンプレートから作成し、内容を埋める:
   - `requirements.md` — ゴール・ユーザーストーリー・制約・受け入れ基準
   - `design.md` — アーキテクチャ・技術選定・データ構造・API・除外スコープ
   - `tasklist.md` — 実装タスクのチェックリスト（依存関係順）

テンプレートは `~/.claude/skills/steering/templates/` にある。

5. 作成したドキュメントをユーザーに提示し、承認を求める

## モード 2: 実装（implement）

`tasklist.md` の未完了タスクを順番に実行する。

### 手順

1. `.steering/` 内の最新ディレクトリ（日付が最新）を探す
2. `tasklist.md` を読み、`[ ]` の未完了タスクを確認する
3. 最初の未完了タスクから順に実装する
4. 各タスク完了後:
   - `tasklist.md` の該当行を `[x]` に更新する
   - 実装内容を簡潔にコメントする
5. すべてのタスクが完了したらユーザーに報告する

## モード 3: 振り返り（retrospective）

実装完了後に学びを記録する。

### 手順

1. `.steering/` 内の最新ディレクトリを探す
2. `tasklist.md` の末尾に振り返りセクションを追記する:

```markdown
## 振り返り

**完了日**: YYYY-MM-DD

### よかった点

- （実装で上手くいったこと）

### 改善点

- （次回に向けた改善点）

### 学んだこと

- （技術的・プロセス的な気づき）
```

3. ユーザーに内容を確認してもらい、追記があれば反映する
